## Lessons learned

- crystal-mysql's prepared protocol rejects MySQL transaction-control commands; Grant must use unprepared.exec for begin, commit, rollback, and savepoint statements.
- Grant's MySQL UUID schema is CHAR(36), while the driver encodes Crystal UUID parameters as 16-byte binary; Grant binds the canonical UUID string.
- crystal-mysql defaults to utf8_general_ci (utf8mb3). Grant uses utf8mb4 by default so four-byte Unicode values can be bound to MySQL 8 utf8mb4 columns.
- MySQL returns DB::ExecResult for bulk DML without RETURNING; Grant uses exec for those paths. MySQL zero changed rows also needs a tenant-scope existence check before raising a tenant mismatch.
- MySQL reports JSON columns with protocol type code 245, and bounded bulk writes need a derived table around limited target-key subqueries.
- A zero-row MySQL update can mean a matched row had no changed values, not that the row belongs to a different tenant.

## Root causes and evidence

- **Shared fixtures:** generic query fixture names/tables overlapped other spec models. Query and STI fixtures now use distinct names and tables, and association foreign keys are explicit where generated names would be ambiguous.
- **Shared runtime state:** registry tests can clear or replace connections, while adapter selection and schema-tenant helpers could retain a stale adapter. Spec setup/teardown restores the connection context, default registry connections, and default database; schema tenancy resolves its adapter again after registry changes.
- **MySQL protocol and dialect behavior:** transaction commands used prepared execution, bounded writes emitted a LIMIT inside an IN subquery, bulk DML expected a result set, UUIDs were bound in a different representation from the CHAR schema, and the client charset default rejected emoji. Each path now follows MySQL's protocol or SQL behavior.
- **MySQL row-count semantics:** tenant updates treated zero changed rows as proof of a tenant mismatch. A visibility query now distinguishes an unchanged matched row from an out-of-scope row.
- **Test SQL portability:** the defaults spec used standard DEFAULT VALUES, unsupported by MySQL; the test now emits MySQL's empty-column insert syntax. SQL identifier assertions use each adapter's quote function.

## Lessons learned

- crystal-mysql's prepared protocol rejects MySQL transaction-control commands; Grant must use unprepared.exec for begin, commit, rollback, and savepoint statements.
- Grant's MySQL UUID schema is CHAR(36), while the driver encodes Crystal UUID parameters as 16-byte binary; Grant binds the canonical UUID string.
- crystal-mysql defaults to utf8_general_ci (utf8mb3). Grant uses utf8mb4 by default so four-byte Unicode values can be bound to MySQL 8 utf8mb4 columns.
- MySQL returns DB::ExecResult for bulk DML without RETURNING; Grant uses exec for those paths. MySQL zero changed rows also needs a tenant-scope existence check before raising a tenant mismatch.
- MySQL reports JSON columns with protocol type code 245, and bounded bulk writes need a derived table around limited target-key subqueries.
- A zero-row MySQL update can mean a matched row had no changed values, not that the row belongs to a different tenant.

### Follow-up lessons learned

- Crystal alpha 1.21.0's OpenSSL bindings can still reference five legacy symbols that OpenSSL 3.6.4 no longer exports; the isolated-file link check needs temporary compatibility aliases to `SSL_get1_peer_certificate`, `EVP_MD_get_size`, and the three `EVP_CIPHER_get_*` functions.
- MySQL timestamp precision requires fractional-second DDL (`TIMESTAMP(6)` and `CURRENT_TIMESTAMP(6)`) as well as fractional binding; update adapter-specific SQL expectations when adding precision support.
- A regression-gate result of no regressions does not prove every current file passes if the base already has aborts; inspect current per-file statuses separately.


## Root causes and evidence

- **Shared fixtures:** generic query fixture names/tables overlapped other spec models. Query and STI fixtures now use distinct names and tables, and association foreign keys are explicit where generated names would be ambiguous.
- **Shared runtime state:** registry tests can clear or replace connections, while adapter selection and schema-tenant helpers could retain a stale adapter. Spec setup and teardown restore the connection context, default registry connections and database, timezone, index-hint and IN-clause settings, tenant context, health-monitor test mode, and log backend.
- **MySQL protocol and dialect behavior:** transaction commands used prepared execution, bounded writes emitted a LIMIT inside an IN subquery, bulk DML expected a result set, UUIDs were bound in a different representation from the CHAR schema, and the client charset default rejected emoji. Each path now follows MySQL's protocol or SQL behavior.
- **MySQL row-count semantics:** tenant updates treated zero changed rows as proof of a tenant mismatch. A visibility query now distinguishes an unchanged matched row from an out-of-scope row.
- **Test SQL portability:** the defaults spec used standard DEFAULT VALUES, unsupported by MySQL; the test now emits MySQL's empty-column insert syntax. SQL identifier assertions use each adapter's quote function.
- **New association/timestamp behavior:** g3 constructor setters, collection `count`/`size`/`empty?`, required `belongs_to`, conditional bulk timestamps, and fractional timestamp support are preserved. Renamed nested fixtures retain explicit association foreign keys through association metadata.
- **MySQL fractional precision:** MySQL's previous second-level `TIMESTAMP` columns discarded the sub-second values required by g3; schema types now use precision six, and the migrator spec expects that adapter-specific SQL. No adapter guard was added.

## MySQL decision classes

- **(a) Grant SQL/adapter fixes:** MySQL's empty insert syntax, limited update subqueries, bulk DML result handling, unchanged-row count semantics, and fractional timestamp DDL/binding are handled by the adapter or Grant SQL generation.
- **(b) Driver limitations fixed in Grant:** transaction-control statements use unprepared execution; UUIDs bind as canonical strings for `CHAR(36)`; JSON protocol values decode as text; and the default connection charset supports `utf8mb4`.
- **(c) Adapter guards:** none. No MySQL spec was guarded or skipped.

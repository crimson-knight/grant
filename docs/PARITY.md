## Prioritized missing features

1. **Configurable optimistic-locking column (locking_column)** (Infrastructure (locking, encryption, instrumentation, …)) — Column name lock_version is hard-coded in src/grant/locking/optimistic.cr (declares column and builds the WHERE). No locking_column override, no automatic activation when a lock_version column exists, no lock_optimistically toggle.
2. **Pessimistic lock! raises on unsaved changes** (Infrastructure (locking, encryption, instrumentation, …)) — lock! just calls reload_with_lock, silently discarding unsaved attribute changes; AR raises to prevent that data loss (unless lock! is given a lock clause on a clean record). Also no lock: option on association reload.
3. **Row-lock unsaved-changes guard (lock! / with_lock on a dirty record)** (Adapters & connections) — reload_with_lock copies fresh values over every column, silently discarding unsaved changes; AR raises RuntimeError 'Locking a record with unsaved changes is not supported'.
4. **Relation#lock with a custom SQL clause or false** (Adapters & connections) — Grant's lock takes only the 6-value LockMode enum. There is no free-form vendor lock string (e.g. 'FOR NO KEY UPDATE', MySQL 'LOCK IN SHARE MODE') and no lock(false) to clear a lock inherited from a scope.
5. **Error message generation from type symbol, message: as Symbol/Proc, errors.add(attr, :type, **options)** (Validations & callbacks) — Messages are hard-coded English strings at macro expansion. errors.add(:name, :blank) does not compile (message is String); `message:` on validators must be a String literal, not a Symbol key or `->(object, data)` proc; no %{count} interpolation.
6. **Errors extras (delete, added?, of_type by type, messages_for, full_message, import/copy!, objects, uniq!, count by attribute)** (Validations & callbacks) — Absent from src/grant/errors.cr: delete(attr, type=nil), added?(attr, type, **opts), messages_for(attr), full_message(attr, msg), import(error, attribute:), copy!(other), objects, uniq!, generate_message, errors.messages Hash accessor, errors.to_hash(true).
7. **Localized error messages and human_attribute_name (I18n)** (Validations & callbacks) — No locale lookup, no Model.human_attribute_name, no per-model/per-attribute message overrides, no format template ('%{attribute} %{message}').
8. **Human-readable names and i18n (human_attribute_name, model_name)** (Core persistence & attributes) — No human_attribute_name or model_name object; error full_messages use raw attribute names.
9. **Validator reflection (validators, validators_on, validate callbacks introspection)** (Validations & callbacks) — __validators_for_validation is internal; no public list of validators per attribute, no kind/options metadata, so form builders and API docs cannot derive maxlength/required.
10. **after_commit/after_rollback on: option (on: [:create, :update, :destroy])** (Validations & callbacks) — Callback macros take only if:/unless:; after_rollback fires regardless of the action while AR after_rollback supports on:. Also AR dedups commit callbacks when the same record is saved several times in one transaction; not verified in Grant.
11. **after_save_commit** (Validations & callbacks) — Not in CALLBACK_NAMES (src/grant/callbacks.cr) or the commit dispatch in src/grant/commit_callbacks.cr.
12. **Callback prepend: true option** (Validations & callbacks) — CALLBACKS entries are always appended; no prepend: (used by dependent: :destroy ordering guidance in Rails).
13. **query cache (within-request result memoization)** (Query interface) — No Model.cache/uncached block or per-request (Amber pipe) query cache. Writes must clear it.
14. **scoping { } block (Model.scoping / Relation#scoping)** (Query interface) — Only unscoped { } exists; no scoping { } that makes a relation the current scope for the block (responds_to? false).
15. **Model.normalize_value_for and normalization on query conditions** (Validations & callbacks) — No public normalize_value_for(attr, value); where(email: " A@X.COM ") and find_by do not normalize the search value while AR does.
16. **Store accessors (store_accessor for JSON column sub-keys)** (Core persistence & attributes) — No store or store_accessor macro. serialized_column exists and could back it.
17. **has_secure_password (ActiveModel::SecurePassword)** (Core persistence & attributes) — No has_secure_password, password=, password_confirmation, authenticate(_password), password_challenge, or bcrypt integration (grep of src).
18. **validate: option and validation of new associated records on owner save** (Associations) — Owner validation never inspects staged/new children; an invalid child surfaces as an exception from save! in after_save, not as owner.valid? == false with errors. No validate: false opt-out. validates_associated exists as a separate macro.
19. **belongs_to association_changed? / association_previously_changed?** (Associations) — Not generated, although the FK column has _changed?/_was.
20. **belongs_to default: option** (Associations) — Not supported.
21. **belongs_to dependent (:destroy / :delete / :destroy_async)** (Associations) — The belongs_to macro has no dependent handling; the option is silently ignored.
22. **destroyed_by_association** (Associations) — Children destroyed by dependent: :destroy cannot tell in their callbacks that the parent triggered the destroy.
23. **index_errors option for association errors** (Associations) — Child errors are not attached to the owner with indexed keys such as posts[0].title.
24. **mark_for_destruction / marked_for_destruction?** (Associations) — Not present; nested attributes handle _destroy with a private flow instead.
25. **Scatter-gather aggregates (sum/average/minimum/maximum/calculate) on sharded models** (Multiple databases & sharding) — Probe: ProbeRec.sum(:tenant_id) raises 'No shard context'. Only count, exists?, pluck are routed.
26. **find_each across all shards** (Multiple databases & sharding) — Probe on real SQLite shards: find_each(batch_size: 3) yielded 12 rows for 10 records (duplicates and nondeterministic), because inside each with_shard the batch query is scatter-gathered across all shards again and offsets are per shard. Cited evidence covers non-sharded find_each only. No start/finish/order/error_on_ignore options on the sharded path; serial across shards.
27. **Shard key immutability enforcement** (Multiple databases & sharding) — Saving a changed shard key is not guarded. Additionally, save/update on a loaded sharded record raises 'No shard context' outside with_shard (current_shard is nil after loading), so the guard needs record shard tracking first.
28. **Cross-shard join detection** (Multiple databases & sharding) — No cross-shard join guard exists.
29. **Automatic role-switching middleware (DatabaseSelector equivalent)** (Multiple databases & sharding) — Grant has no Amber/HTTP::Handler that routes GET/HEAD to reading and other verbs to writing, nor per-session last-write tracking.
30. **Database URL / DATABASE_URL configuration and adapter inference from URL scheme** (Adapters & connections) — establish_connection requires the adapter class explicitly; the URL scheme (postgres://, mysql://, sqlite3:) is never used to choose one and DATABASE_URL is not read. Custom adapter registration by name (ConnectionAdapters.register) does not exist either.
31. **Multi-database configuration (database.yml configurations, replica: true, DATABASE_URL)** (Multiple databases & sharding) — No declarative per-environment multi-database config. Connections are registered in code only via establish_connection(s); no configs_for(env, name), replica marker, DATABASE_URL merge, or database_tasks flag.
32. **ShardSelector middleware (shard_resolver, lock)** (Multiple databases & sharding) — No request middleware that picks a shard per request (e.g. from tenant/subdomain) and optionally locks it.
33. **Database configurations API (db_config, configs_for, per-environment named configs)** (Adapters & connections) — There is no config object model (HashConfig/UrlConfig equivalent) or lookup by environment/name; settings live only as ConnectionRegistry specs keyed by 'db:role[:shard]'. Loading a database.yml-shaped file is left to the app (Amber's environment YAML).
34. **Encryption: filter_parameters and inspect masking of encrypted attributes** (Infrastructure (locking, encryption, instrumentation, …)) — No filter_attributes; grep finds no inspect override on models. Plaintext appears in inspect, logs of bound values and exceptions.
35. **Encryption: previous: schemes for key/scheme migration** (Infrastructure (locking, encryption, instrumentation, …)) — Only one active key; rotation is a batch re-encrypt helper (MigrationHelpers.rotate_encryption), not read-with-old, write-with-new. No multiple primary keys and no per-attribute previous schemes, so a rotation requires a maintenance window.
36. **Encryption: transparent same-name column and non-String attribute types** (Infrastructure (locking, encryption, instrumentation, …)) — encrypts creates a virtual String accessor over a <attr>_encrypted column; the original column name is not usable, where(email: ...) is not rewritten, and Int/Time/JSON values cannot be encrypted.
37. **Encryption context and record helpers (encrypted_attribute?, ciphertext_for, encrypt, decrypt, without_encryption, protecting_encrypted_data)** (Infrastructure (locking, encryption, instrumentation, …)) — encrypted_attributes registry exists but there is no instance ciphertext_for/encrypted_attribute?/encrypt/decrypt, and no scoped blocks to disable or pin encryption (keys, encryptor) per fiber.
38. **Encryption: ignore_case: and downcase: options** (Infrastructure (locking, encryption, instrumentation, …)) — Not supported by the encrypts macro; case-insensitive deterministic lookup requires the caller to downcase manually.
39. **Encryption: compress: option** (Infrastructure (locking, encryption, instrumentation, …)) — No compression before encrypting; large text columns are stored uncompressed.
40. **alter_table / change_column / add_column at runtime via Grant DSL** (Migrations & schema) — No ALTER TABLE DSL of any kind (add/remove/change column, null, default, change_table bulk). SQLite needs a table rebuild for change_column.
41. **references / belongs_to columns in migrations (add_reference, remove_reference, polymorphic)** (Migrations & schema) — No reference helper; polymorphic `_type`/`_id` pair, index, and FK creation must be hand-written.
42. **rename_column / rename_index DSL** (Migrations & schema) — No rename_column/rename_index; AR also renames default-named indexes on column rename.
43. **PostgreSQL enum types, extensions, and custom column types (create_enum, enable_extension, hstore, citext, jsonb, inet, ltree, money)** (Migrations & schema) — No DDL for enums or extensions; type table lacks these types. `column_type:` verbatim works as a workaround.
44. **Unique constraints and exclusion constraints** (Migrations & schema) — No DDL. Migrator never emits UNIQUE, even for validates_uniqueness_of fields.
45. **create_join_table / drop_join_table** (Migrations & schema) — No join-table DDL helper (name derivation from two tables, FK columns, optional index).
46. **rename_table DSL** (Migrations & schema) — No rename_table DSL (which in AR also renames the pk sequence and indexes).
47. **Table and column comments** (Migrations & schema) — No comment DDL (PG COMMENT ON, MySQL COMMENT clause; SQLite unsupported).
48. **Migration class: up/down/change with versioned class ([8.0] compat)** (Migrations & schema) — No Migration base class or per-version compatibility layer; migrations are SQL files for external Micrate. Compat layers (ActiveRecord::Migration::Compatibility) are Rails-history specific.
49. **MigrationContext operations: migrate to version, rollback(step), redo, up/down(version), forward, status** (Migrations & schema) — None present in Grant; must go through Micrate CLI.
50. **Concurrency safety: migration advisory locks** (Migrations & schema) — No migration runner and no advisory-lock helper in Grant, so two deploy nodes can run the same DDL concurrently.
51. **DDL transactions and disable_ddl_transaction!** (Migrations & schema) — No migration runner, so no per-migration transaction wrapping and no opt-out (needed for CREATE INDEX CONCURRENTLY on PG). MySQL does not support transactional DDL.
52. **Multi-database migrations (per-connection migrations_paths, db:migrate:primary, connection-specific tasks)** (Migrations & schema) — Grant has named connections and sharding, but no migration runner targets one by name, and there is no per-connection schema_migrations. Schema-tenant (PG search_path) migrations across tenants are also absent.
53. **Pending-migration check and maintain_test_schema** (Migrations & schema) — No detection of pending migrations at boot/in specs and no auto load of the test schema.
54. **Shard-aware migrations** (Multiple databases & sharding) — Rails migrates every database in the environment configuration, including shard entries, with a per-database migrations_paths and schema dump; Grant's Migrator is per-model adapter only and has no run-on-all-configured-connections task.
55. **ar_internal_metadata environment protection** (Migrations & schema) — No metadata table storing environment, so destructive tasks (drop/reset) in production are not blocked. `Migrator#drop_and_create` is unguarded.
56. **Advisory locks (PostgreSQL pg_advisory_lock / MySQL GET_LOCK)** (Infrastructure (locking, encryption, instrumentation, …)) — No adapter API for advisory locks. Rationale for n.a. (not core) is not a Ruby-metaprogramming reason; AR ships these as adapter methods used by the migrator.
57. **Migration output and helpers: say, say_with_time, announce, suppress_messages** (Migrations & schema) — No migration runner output layer; could reuse Grant::Log.
58. **Migrator advisory lock (concurrent migrate protection)** (Infrastructure (locking, encryption, instrumentation, …)) — No lock preventing two processes from running migrations at once on PG or MySQL.
59. **with / with_recursive (common table expressions)** (Query interface) — Absent (responds_to? false); no WITH clause support in the assemblers.
60. **from (custom FROM clause / subquery as table)** (Query interface) — No Relation#from(source, subquery_name = nil) (responds_to? false); no unscope(:from).
61. **delegated types** (Associations) — No delegated_type macro. Everything it needs (polymorphic belongs_to, has_one as:, enum-style predicates) exists separately, but only for Int64 keys.
62. **Fixtures / test helpers (ActiveRecord::FixtureSet equivalent)** (Infrastructure (locking, encryption, instrumentation, …)) — No YAML fixture loader, no label-to-id hashing, no fixture accessors, no transactional-test wrapper.
63. **QueryLogs with context tags (SQL comment injection)** (Infrastructure (locking, encryption, instrumentation, …)) — annotate exists per query, but no global tag config, no fiber-local context, no automatic prepend of model/controller/action/job tags.
64. **Verbose query logs (source location of SQL) and log tags with binds** (Infrastructure (locking, encryption, instrumentation, …)) — SQL log shows query with colorized params but no calling file:line, no query-name label (User Load), no cached-hit marker.
65. **Schema dump / schema.rb equivalent** (Migrations & schema) — No dump, no load, no schema file format, and no introspection layer to build one from.
66. **Database tasks (create/drop/purge/migrate/schema load, DatabaseTasks)** (Infrastructure (locking, encryption, instrumentation, …)) — Grant relies on external Micrate and the Amber CLI for these operations; no Grant-level programmatic create/drop/purge/prepare API and no structure-dump load.
67. **Database tasks: create/drop database, purge, structure dump (structure.sql), setup/reset/prepare, truncate_all** (Migrations & schema) — No Grant API; Micrate/Amber CLI does create/drop only. No structure dump/load, purge, `db:prepare`, `db:reset`, or `truncate_all`.
68. **Schema format configuration (:ruby vs :sql) and db:schema:load for fresh environments** (Migrations & schema) — Depends on the schema dump row; nothing to select or load.
69. **Migration file generator naming conventions (AddXToY, CreateXs parse, timestamped versions)** (Migrations & schema) — Covered only inside the external Amber CLI row; no attribute parsing DSL in Grant.
70. **query_constraints composite model keys** (Infrastructure (locking, encryption, instrumentation, …)) — No API to scope find/update/destroy/reload by multiple columns while keeping a single-column primary key (for example a sharded or tenant-partitioned key).
71. **composite foreign keys on associations (query_constraints)** (Associations) — Association macros assume a single foreign key and primary key column; composite primary keys exist in src/grant/composite_primary_key.cr but associations do not use them.
72. **association option validation (unknown keys and dependent: values raise)** (Associations) — Macros take **options and ignore unknown keys; an invalid dependent: (e.g. :restrict_with_error, :delete on has_many) is silently accepted (probe P3). AR raises ArgumentError for both.
73. **nested has_many :through (through another through association)** (Associations) — AssociationCollection#through_associations does a single registry lookup; if the through association is itself a through, the join keys are wrong. No spec exists.
74. **singular association builders build_<assoc> / create_<assoc> / create_<assoc>!** (Associations) — Not generated (probe P6: responds_to?(:build_prb_detail) and :create_prb_detail are false).
75. **has_many :through source_type (polymorphic source)** (Associations) — No source_type option; a through whose source is a polymorphic belongs_to cannot be expressed.
76. **Adapter session variables (PostgreSQL statement_timeout/lock_timeout/search_path/application_name, MySQL variables/sql_mode)** (Adapters & connections) — There is no per-connection variables hook, so statement_timeout, lock_timeout, application_name, default search_path and MySQL sql_mode cannot be set declaratively; no per-query timeout. MySQL adapter only forces utf8mb4 encoding. Deferred: crystal-db has no on-connect hook, so this needs an upstream or wrapped-connection factory. A SET on every checkout would double round trips.
77. **Encryption: pluggable key_provider, encryptor, message_serializer, AES-GCM cipher** (Infrastructure (locking, encryption, instrumentation, …)) — KeyProvider is a concrete class with class-level state. Cipher is CBC+HMAC with a custom byte layout, so ciphertext is not interoperable with Rails data. No envelope-encryption provider (KMS) and no swappable encryptor. Deferred: Changing the cipher or payload layout breaks existing ciphertext. Needs a versioned payload design and a rotation plan first. Rails-compatible messages are a separate decision.
78. **Callback objects (before_save MyCallback.new / class with before_save(record))** (Validations & callbacks) — Callbacks accept a method Symbol or a block only; no object with a before_save(record) protocol for shared, testable callback classes. Deferred: Low value. A method Symbol or block already covers the use; the callback-object protocol adds compile-time surface for little benefit.
79. **Database-specific types: PostgreSQL hstore** (Infrastructure (locking, encryption, instrumentation, …)) — No Hash(String, String?) column type, no migration type or operators. Deferred: Low value, PG only, and JSONB covers the main use.
80. **Database-specific types: PostgreSQL ranges, network (inet/cidr/macaddr), interval, native enum, citext** (Infrastructure (locking, encryption, instrumentation, …)) — Only PG::Interval appears in the adapter's allowed type list and no spec covers it. No Range(T,T) column mapping, no Socket::IPAddress column, no PG CREATE TYPE enum mapping or citext. Deferred: Effort L, low value, and range bound normalization makes dirty tracking risky. Take individual types on demand.
81. **Generated (virtual/stored) columns** (Migrations & schema) — No DDL for generated columns; must use verbatim `column_type:`. Deferred: Low value and overlaps the Infrastructure virtual-column row. Verbatim column_type: works as a workaround. Do both together later.
82. **Lazy transactions (deferred BEGIN)** (Adapters & connections) — BEGIN is sent immediately on every transaction block, even ones that run no query or only reads that a cache satisfies; AR defers BEGIN until the first statement. Deferred: Low value, effort L, and lazy checkout mid-block risks starving the pool. Revisit after T01 lands and benchmarks show empty-transaction cost.
83. **Views (create_view/drop_view) and materialized views** (Migrations & schema) — No view DDL or view-backed model helpers; `view_exists?`/`views` introspection absent. Deferred: Low value, and needs PG-specific refresh semantics. Raw execute covers it until the DDL DSL (M02b) is stable.
84. **has_many :through disable_joins** (Associations) — No option; Grant's through query already uses an IN subquery rather than a JOIN, so cross-database through is not available. Deferred: Low value and effort M. Merge with Cross-database associations (has_many / has_one through with disable_joins: true), which is a duplicate. Revisit after A02.
85. **skip_callback / set_callback / define_callbacks / reset_callbacks (custom callback chains)** (Validations & callbacks) — No way to skip an inherited callback in a subclass or define new callback chains; runtime per-call skipping is impossible with compile-time chains. Callback chain is a compile-time constant, so run-time mutation is Ruby-metaprogramming-shaped. Deferred: Effort L, low value, and compile-time chains make Ruby-style runtime mutation a poor fit. Revisit after CB01.

## Prioritized missing features

1. **Unified validates macro (AR style: validates :field, presence: true, length: {min:2})** (Validations & callbacks) — No `validates` macro. Each validator needs its own macro call; no per-attribute option hash, no shared if:/unless:/on:/allow_nil/allow_blank/strict/message defaults across sub-validators, no custom-validator lookup by key (`my: true` -> MyValidator).
2. **on: array of contexts and on: for before_validation/after_validation callbacks** (Validations & callbacks) — `on:` on validators is a single symbol; before_validation/after_validation macros accept only if:/unless: (src/grant/callbacks.cr), no on: :create/:update.
3. **save/save!/create with context: (validation_context accessor)** (Validations & callbacks) — save derives :create/:update itself (src/grant/transactions.cr) and accepts only validate:/skip_timestamps:. No context: kw, no validation_context reader available to custom validators/callbacks during a run.
4. **validate! (raises RecordInvalid, accepts context)** (Validations & callbacks) — No validate!/validate(context) alias; grep of src/ finds none.
5. **Callback conditions as arrays and combined if:+unless: lists** (Validations & callbacks) — Callback and validator macros accept a single SymbolLiteral or proc; an array like `if: [:a?, ->(r) { ... }]` is not handled (callbacks.cr and the validator prologues test only is_a?(SymbolLiteral)).
6. **strict: option on validators (raises instead of adding to errors)** (Validations & callbacks) — No strict: option. Depends on Grant::ValidationError (ActiveModel::StrictValidationFailed) existing; neither present.
7. **Partial updates (UPDATE only changed columns; no-op save when clean)** (Core persistence & attributes) — __update in src/grant/transactions.cr builds fields from content_fields (every non-PK column) and writes them all; save on an unchanged record still issues UPDATE and bumps updated_at (AR issues no SQL when nothing changed). Consequences: lost-update overwrites of columns another writer changed, wider write lock and WAL/binlog volume, spurious updated_at bumps.
8. **Record equality and hashing (==, eql?, hash by class and primary key)** (Core persistence & attributes) — No def ==/hash in src, so Crystal reference equality applies: two instances loaded from the same row are not equal, Array#includes?/uniq/Set and == in specs behave differently from Rails. New records must stay unequal unless identical.
9. **Destroyed-record guard (frozen after destroy; save/update/touch raise)** (Core persistence & attributes) — destroyed? is set but no path checks it: grep of src/grant/transactions.cr shows no destroyed? guard in save, update, touch, update_columns or increment!, so saving a destroyed record attempts an UPDATE that affects zero rows and can report success.
10. **dup / clone semantics for records** (Core persistence & attributes) — No dup/clone override. Crystal default dup shallow-copies ivars: new_record stays false, primary key and timestamps are copied, and the @original_attributes/@changed_attributes/@previous_changes hashes are shared by reference so changes on the copy leak into the original's dirty state. AR dup yields a new record with cleared PK and timestamps and independent state.
11. **no_touching / suppress blocks** (Core persistence & attributes) — No block-scoped suppression of touch or save; only per-call skip_timestamps:.
12. **touch: and time: options on touch, increment!, decrement!, toggle!, update_counters** (Core persistence & attributes) — touch(*fields) always uses Time.local now (no time:). increment!/decrement! accept only by:, no touch:. AR 8 also cascades belongs_to touch on #touch.
13. **update_column (singular)** (Core persistence & attributes) — Only update_columns(**args) exists; the singular form is a public AR method (grep finds no def update_column).
14. **Class-level destroy(id/ids), delete(id/ids), update(id/ids, attrs)** (Core persistence & attributes) — No class-level destroy(id), delete(id) or update(id, attrs) in src (grep). Class-level destroy_all/delete_all/update_all work through the builder delegation.
15. **Relation build / create / create! / new with scope attributes, create_with, scope_attributes** (Query interface) — Builder has no create/build/new (responds_to? false); create_with absent; where_values_hash absent. Scope-derived attributes (Post.where(published: true).build) are not applied.
16. **Relation new / build / create / create! inheriting where-hash attributes** (Core persistence & attributes) — Grant::Query::Builder has no new/build/create (grep of builder.cr), so Model.where(active: true).create/new does not pre-fill the equality attributes the way AR does; only class-level create exists.
17. **create_or_find_by (unique-constraint race-safe create)** (Core persistence & attributes) — No implementation, and there is no typed unique-violation error to rescue (grep for unique violation/RecordNotUnique in src finds none); driver errors surface as DB::Error.
18. **create_with relation defaults** (Core persistence & attributes) — No Builder#create_with, and (see relation new/create untracked row) the builder has no new/build/create at all for it to feed.
19. **first_or_create / first_or_create! / first_or_initialize** (Core persistence & attributes) — Not present in src (grep). Note first_or_create is soft-deprecated in AR in favor of find_or_create_by but still public.
20. **new / build with initializer block** (Core persistence & attributes) — Model.new(**args), new(Hash), new accept no block; AR yields self before after_initialize.
21. **insert / insert! (single-row AR8)** (Core persistence & attributes) — No single-row insert/insert!/upsert; only the *_all forms.
22. **or / and with a relation argument and structural-compatibility check** (Query interface) — Post.where(a: 1).or(Post.where(b: 2)) form absent; only flat kw/string or and block or. AR raises ArgumentError for structurally incompatible relations (differing joins/limit/etc.).
23. **where with nested table hash / joined-table columns / record values** (Query interface) — structured_field_sql only accepts columns present in Model.fields, so joined-table columns in a hash fail with 'Unknown query field'; nested hash form and where(association: record) / where(fk: record) not supported.
24. **where(association: record) association-aware predicates** (Associations) — Builder#where(**matches) treats keys as column names; passing an association name with a record is not resolved to the FK (and type for polymorphic). Source-read only, not probed.
25. **where with named bind placeholders** (Query interface) — Only positional ? binds; :name named binds unsupported in Builder#where and sanitize_sql_array (grep of sanitization.cr finds no named handling).
26. **where.associated** (Query interface) — Only Grant's non-AR where.has(association, table:, foreign_key:) exists; the AR spelling where.associated(:assoc) is absent (see where.missing / where.has row).
27. **where.not with hash / multi-condition (NAND) and non-scalar values** (Query interface) — WhereChain#not(field, value) accepts one scalar pair. AR where.not(a: 1, b: 2) (NOT (a=1 AND b=2)), arrays (NOT IN), nil (IS NOT NULL), ranges are unsupported via the keyword form (the block form exists).
28. **excluding / without (exclude given records)** (Query interface) — Absent (Post.excluding(post1, post2)).
29. **invert_where** (Query interface) — Absent.
30. **grouped aggregations returning Hash (group.sum/average/minimum/maximum)** (Query interface) — Only count honors group_fields (Q-12). group_by(:name).sum(:id) returned scalar 0.0 in a scratch probe (GROUP BY silently ignored by the sum path in aggregations.cr), a silent wrong-result hazard.
31. **order with raw SQL / expressions / NULLS FIRST-LAST** (Query interface) — order accepts only column symbols with :asc/:desc; no order('lower(name) DESC'), no nulls_first/nulls_last, no expression ordering, no order on joined-table column.
32. **calculate (generic aggregation method)** (Query interface) — Named aggregates exist; calculate(:count/:sum/:average/:minimum/:maximum, column) is absent (responds_to? false on relation and model).
33. **extract_associated** (Query interface) — Absent (Post.where(...).extract_associated(:author)).
34. **in_order_of (order by explicit value list)** (Query interface) — Absent. AR 7+/8 in_order_of(:col, values, filter: true) also filters to the given values.
35. **readonly relations (prevent persistence on fetched records)** (Query interface) — No Relation#readonly / unscope(:readonly). Record-level readonly!/readonly? and ReadOnlyRecordError exist (transactions.cr; spec/grant/persistence_helpers_spec.cr) so only the relation flag that marks each hydrated record is missing.
36. **Relation update / update! (per-record with callbacks)** (Query interface) — Only update_all (SQL, no callbacks) exists on Builder; no Relation#update(attrs) or update(id, attrs) running validations and callbacks per record (responds_to? false).
37. **Introspection: table_exists?, column_exists?, columns, tables, primary_key, indexes, foreign_keys** (Migrations & schema) — No catalog introspection (grep of src/ finds only schema_tenant's schemata query). Blocks schema dump, idempotent migrations, and model/table drift checks.
38. **Schema cache / schema introspection API** (Infrastructure (locking, encryption, instrumentation, …)) — Column metadata is compile-time macro state (column_for_attribute exists) but there is no runtime introspection of the actual DB: no tables/columns/indexes/foreign_keys query API, no table_exists?/column_exists?, no dump and load of a cache file, no drift check between declared and actual columns.
39. **Integration cache keys and to_param (cache_key, cache_version, collection_cache_key)** (Infrastructure (locking, encryption, instrumentation, …)) — No cache_key/cache_version derived from updated_at and no relation-level collection_cache_key; no to_param override hook.
40. **inspect with filter_attributes (redacted, readable inspect)** (Core persistence & attributes) — No inspect override, so Crystal's default dumps every ivar including the three dirty-tracking hashes, encrypted or password columns, and secure tokens, into logs and error messages. AR prints only attributes and masks filter_attributes.
41. **to_param / to_key / cache_key / cache_version / cache_key_with_version** (Core persistence & attributes) — None defined (grep). Amber V2 route helpers and view code need a string id; cache keys are needed for fragment caching.
42. **alias_attribute** (Core persistence & attributes) — No alias_attribute macro (grep). Where clauses also would not resolve aliases.
43. **attribute_before_type_cast** (Core persistence & attributes) — No raw-before-cast reader. Typed setters take typed values, so raw values only exist on the mass-assignment path (Grant::Type.convert_type in set_attributes), which discards them.
44. **Instrumentation notifications (sql / transaction / instantiation / strict_loading_violation events with payload)** (Infrastructure (locking, encryption, instrumentation, …)) — Only Log sub-loggers. No subscribe API with structured payload (sql, binds, name, duration, connection, cached, async), so APMs and query counters cannot hook in typed.
45. **Transactional test wrapper (use_transactional_tests equivalent)** (Adapters & connections) — No helper that opens a joinable:false transaction around each example and rolls it back, across all registered connections. The suite instead clears tables.
46. **Transaction instrumentation events (transaction.active_record, start_transaction.active_record)** (Adapters & connections) — SQL logging exists (Instrumentation area) but there are no transaction-level events with outcome (commit/rollback/restart) for APM or slow-transaction detection.
47. **Pool disconnect and teardown (disconnect!, clear_all_connections!, remove_connection)** (Adapters & connections) — No adapter close/disconnect exists anywhere in src. ConnectionRegistry.clear_all and re-establish_connection drop the Adapter reference without closing its DB::Database pool, leaking sockets and (for SQLite) file handles; the spec titled 'closes existing pool when re-establishing connection' only checks the new URL.
48. **Connection pool introspection and lifecycle (stat, size, idle/busy, reaping, max_age, min_connections)** (Multiple databases & sharding) — No stat (size, connections, busy, idle, waiting), no reap/flush, and none of max_age, min_connections, keepalive, idle_timeout. Depends on crystal-db pool stats (DB::Pool exposes stats).
49. **Pool idle/reaper settings (idle_timeout, reaping_frequency, min_connections, keepalive)** (Adapters & connections) — ConnectionSpec exposes pool_size, initial_pool_size, checkout_timeout, retry_attempts, retry_delay and health check timing only. crystal-db has max_idle_pool_size but no time-based idle reaping; Grant adds no reaper, so server-side idle connection kills (PgBouncer, cloud proxies) produce lost-connection errors on the next checkout.
50. **Pool statistics (connection_pool.stat)** (Adapters & connections) — No Grant-level pool introspection. crystal-db exposes DB::Database#pool.stats (open, idle, in_flight, max), unused by Grant, and ConnectionRegistry.health_status reports only healthy/unhealthy.
51. **Prepared statements / statement caching** (Adapters & connections) — Restated: crystal-db already caches prepared statements per connection (StringKeyCache in lib/db/src/db/connection.cr) and honors prepared_statements / prepared_statements_cache URL parameters, so the row's 'no cache exists' is inaccurate. What is missing is Grant-level control and evidence: ConnectionSpec has no prepared_statements/cache option (only a hand-edited URL passes through build_pool_url), no statement_limit (the driver cache is an unbounded Hash), and no spec. Needed for PgBouncer transaction pooling (prepared_statements=false) and to bound memory when Sanitization inlines literals or IN lists vary in length.
52. **with_connection / lease_connection / release_connection** (Multiple databases & sharding) — No public API to pin one pooled connection to a fiber for several operations (SchemaTenant pins internally only). Grant.transaction is the only path to a single physical connection.
53. **HABTM (has_and_belongs_to_many) equivalent** (Associations) — No has_and_belongs_to_many macro. Depends on has_many :through writers, which are also absent, so HABTM cannot be built from existing pieces yet.
54. **association callbacks (before_add / after_add / before_remove / after_remove)** (Associations) — No options on has_many; no hook when records are added to or removed from a collection.
55. **Configurable optimistic-locking column (locking_column)** (Infrastructure (locking, encryption, instrumentation, …)) — Column name lock_version is hard-coded in src/grant/locking/optimistic.cr (declares column and builds the WHERE). No locking_column override, no automatic activation when a lock_version column exists, no lock_optimistically toggle.
56. **Pessimistic lock! raises on unsaved changes** (Infrastructure (locking, encryption, instrumentation, …)) — lock! just calls reload_with_lock, silently discarding unsaved attribute changes; AR raises to prevent that data loss (unless lock! is given a lock clause on a clean record). Also no lock: option on association reload.
57. **Row-lock unsaved-changes guard (lock! / with_lock on a dirty record)** (Adapters & connections) — reload_with_lock copies fresh values over every column, silently discarding unsaved changes; AR raises RuntimeError 'Locking a record with unsaved changes is not supported'.
58. **Relation#lock with a custom SQL clause or false** (Adapters & connections) — Grant's lock takes only the 6-value LockMode enum. There is no free-form vendor lock string (e.g. 'FOR NO KEY UPDATE', MySQL 'LOCK IN SHARE MODE') and no lock(false) to clear a lock inherited from a scope.
59. **Error message generation from type symbol, message: as Symbol/Proc, errors.add(attr, :type, **options)** (Validations & callbacks) — Messages are hard-coded English strings at macro expansion. errors.add(:name, :blank) does not compile (message is String); `message:` on validators must be a String literal, not a Symbol key or `->(object, data)` proc; no %{count} interpolation.

61. **Localized error messages and human_attribute_name (I18n)** (Validations & callbacks) — No locale lookup, no Model.human_attribute_name, no per-model/per-attribute message overrides, no format template ('%{attribute} %{message}').
62. **Human-readable names and i18n (human_attribute_name, model_name)** (Core persistence & attributes) — No human_attribute_name or model_name object; error full_messages use raw attribute names.
63. **Validator reflection (validators, validators_on, validate callbacks introspection)** (Validations & callbacks) — __validators_for_validation is internal; no public list of validators per attribute, no kind/options metadata, so form builders and API docs cannot derive maxlength/required.

Also AR dedups commit callbacks when the same record is saved several times in one transaction; not verified in Grant.

78. **mark_for_destruction / marked_for_destruction?** (Associations) — Not present; nested attributes handle _destroy with a private flow instead.
79. **Scatter-gather aggregates (sum/average/minimum/maximum/calculate) on sharded models** (Multiple databases & sharding) — Probe: ProbeRec.sum(:tenant_id) raises 'No shard context'. Only count, exists?, pluck are routed.
80. **find_each across all shards** (Multiple databases & sharding) — Probe on real SQLite shards: find_each(batch_size: 3) yielded 12 rows for 10 records (duplicates and nondeterministic), because inside each with_shard the batch query is scatter-gathered across all shards again and offsets are per shard. Cited evidence covers non-sharded find_each only. No start/finish/order/error_on_ignore options on the sharded path; serial across shards.
81. **Shard key immutability enforcement** (Multiple databases & sharding) — Saving a changed shard key is not guarded. Additionally, save/update on a loaded sharded record raises 'No shard context' outside with_shard (current_shard is nil after loading), so the guard needs record shard tracking first.
82. **Cross-shard join detection** (Multiple databases & sharding) — No cross-shard join guard exists.
83. **Automatic role-switching middleware (DatabaseSelector equivalent)** (Multiple databases & sharding) — Grant has no Amber/HTTP::Handler that routes GET/HEAD to reading and other verbs to writing, nor per-session last-write tracking.
84. **Database URL / DATABASE_URL configuration and adapter inference from URL scheme** (Adapters & connections) — establish_connection requires the adapter class explicitly; the URL scheme (postgres://, mysql://, sqlite3:) is never used to choose one and DATABASE_URL is not read. Custom adapter registration by name (ConnectionAdapters.register) does not exist either.
85. **Multi-database configuration (database.yml configurations, replica: true, DATABASE_URL)** (Multiple databases & sharding) — No declarative per-environment multi-database config. Connections are registered in code only via establish_connection(s); no configs_for(env, name), replica marker, DATABASE_URL merge, or database_tasks flag.
86. **ShardSelector middleware (shard_resolver, lock)** (Multiple databases & sharding) — No request middleware that picks a shard per request (e.g. from tenant/subdomain) and optionally locks it.
87. **Database configurations API (db_config, configs_for, per-environment named configs)** (Adapters & connections) — There is no config object model (HashConfig/UrlConfig equivalent) or lookup by environment/name; settings live only as ConnectionRegistry specs keyed by 'db:role[:shard]'. Loading a database.yml-shaped file is left to the app (Amber's environment YAML).
88. **Encryption: filter_parameters and inspect masking of encrypted attributes** (Infrastructure (locking, encryption, instrumentation, …)) — No filter_attributes; grep finds no inspect override on models. Plaintext appears in inspect, logs of bound values and exceptions.
89. **Encryption: previous: schemes for key/scheme migration** (Infrastructure (locking, encryption, instrumentation, …)) — Only one active key; rotation is a batch re-encrypt helper (MigrationHelpers.rotate_encryption), not read-with-old, write-with-new. No multiple primary keys and no per-attribute previous schemes, so a rotation requires a maintenance window.
90. **Encryption: transparent same-name column and non-String attribute types** (Infrastructure (locking, encryption, instrumentation, …)) — encrypts creates a virtual String accessor over a <attr>_encrypted column; the original column name is not usable, where(email: ...) is not rewritten, and Int/Time/JSON values cannot be encrypted.
91. **Encryption context and record helpers (encrypted_attribute?, ciphertext_for, encrypt, decrypt, without_encryption, protecting_encrypted_data)** (Infrastructure (locking, encryption, instrumentation, …)) — encrypted_attributes registry exists but there is no instance ciphertext_for/encrypted_attribute?/encrypt/decrypt, and no scoped blocks to disable or pin encryption (keys, encryptor) per fiber.
92. **Encryption: ignore_case: and downcase: options** (Infrastructure (locking, encryption, instrumentation, …)) — Not supported by the encrypts macro; case-insensitive deterministic lookup requires the caller to downcase manually.
93. **Encryption: compress: option** (Infrastructure (locking, encryption, instrumentation, …)) — No compression before encrypting; large text columns are stored uncompressed.
94. **alter_table / change_column / add_column at runtime via Grant DSL** (Migrations & schema) — No ALTER TABLE DSL of any kind (add/remove/change column, null, default, change_table bulk). SQLite needs a table rebuild for change_column.
95. **references / belongs_to columns in migrations (add_reference, remove_reference, polymorphic)** (Migrations & schema) — No reference helper; polymorphic `_type`/`_id` pair, index, and FK creation must be hand-written.
96. **rename_column / rename_index DSL** (Migrations & schema) — No rename_column/rename_index; AR also renames default-named indexes on column rename.
97. **PostgreSQL enum types, extensions, and custom column types (create_enum, enable_extension, hstore, citext, jsonb, inet, ltree, money)** (Migrations & schema) — No DDL for enums or extensions; type table lacks these types. `column_type:` verbatim works as a workaround.
98. **Unique constraints and exclusion constraints** (Migrations & schema) — No DDL. Migrator never emits UNIQUE, even for validates_uniqueness_of fields.
99. **create_join_table / drop_join_table** (Migrations & schema) — No join-table DDL helper (name derivation from two tables, FK columns, optional index).
100. **rename_table DSL** (Migrations & schema) — No rename_table DSL (which in AR also renames the pk sequence and indexes).
101. **Table and column comments** (Migrations & schema) — No comment DDL (PG COMMENT ON, MySQL COMMENT clause; SQLite unsupported).
102. **Migration class: up/down/change with versioned class ([8.0] compat)** (Migrations & schema) — No Migration base class or per-version compatibility layer; migrations are SQL files for external Micrate. Compat layers (ActiveRecord::Migration::Compatibility) are Rails-history specific.
103. **MigrationContext operations: migrate to version, rollback(step), redo, up/down(version), forward, status** (Migrations & schema) — None present in Grant; must go through Micrate CLI.
104. **Concurrency safety: migration advisory locks** (Migrations & schema) — No migration runner and no advisory-lock helper in Grant, so two deploy nodes can run the same DDL concurrently.
105. **DDL transactions and disable_ddl_transaction!** (Migrations & schema) — No migration runner, so no per-migration transaction wrapping and no opt-out (needed for CREATE INDEX CONCURRENTLY on PG). MySQL does not support transactional DDL.
106. **Multi-database migrations (per-connection migrations_paths, db:migrate:primary, connection-specific tasks)** (Migrations & schema) — Grant has named connections and sharding, but no migration runner targets one by name, and there is no per-connection schema_migrations. Schema-tenant (PG search_path) migrations across tenants are also absent.
107. **Pending-migration check and maintain_test_schema** (Migrations & schema) — No detection of pending migrations at boot/in specs and no auto load of the test schema.
108. **Shard-aware migrations** (Multiple databases & sharding) — Rails migrates every database in the environment configuration, including shard entries, with a per-database migrations_paths and schema dump; Grant's Migrator is per-model adapter only and has no run-on-all-configured-connections task.
109. **ar_internal_metadata environment protection** (Migrations & schema) — No metadata table storing environment, so destructive tasks (drop/reset) in production are not blocked. `Migrator#drop_and_create` is unguarded.
110. **Advisory locks (PostgreSQL pg_advisory_lock / MySQL GET_LOCK)** (Infrastructure (locking, encryption, instrumentation, …)) — No adapter API for advisory locks. Rationale for n.a. (not core) is not a Ruby-metaprogramming reason; AR ships these as adapter methods used by the migrator.
111. **Migration output and helpers: say, say_with_time, announce, suppress_messages** (Migrations & schema) — No migration runner output layer; could reuse Grant::Log.
112. **Migrator advisory lock (concurrent migrate protection)** (Infrastructure (locking, encryption, instrumentation, …)) — No lock preventing two processes from running migrations at once on PG or MySQL.
113. **with / with_recursive (common table expressions)** (Query interface) — Absent (responds_to? false); no WITH clause support in the assemblers.
114. **from (custom FROM clause / subquery as table)** (Query interface) — No Relation#from(source, subquery_name = nil) (responds_to? false); no unscope(:from).
115. **delegated types** (Associations) — No delegated_type macro. Everything it needs (polymorphic belongs_to, has_one as:, enum-style predicates) exists separately, but only for Int64 keys.
116. **Fixtures / test helpers (ActiveRecord::FixtureSet equivalent)** (Infrastructure (locking, encryption, instrumentation, …)) — No YAML fixture loader, no label-to-id hashing, no fixture accessors, no transactional-test wrapper.
117. **QueryLogs with context tags (SQL comment injection)** (Infrastructure (locking, encryption, instrumentation, …)) — annotate exists per query, but no global tag config, no fiber-local context, no automatic prepend of model/controller/action/job tags.
118. **Verbose query logs (source location of SQL) and log tags with binds** (Infrastructure (locking, encryption, instrumentation, …)) — SQL log shows query with colorized params but no calling file:line, no query-name label (User Load), no cached-hit marker.
119. **Schema dump / schema.rb equivalent** (Migrations & schema) — No dump, no load, no schema file format, and no introspection layer to build one from.
120. **Database tasks (create/drop/purge/migrate/schema load, DatabaseTasks)** (Infrastructure (locking, encryption, instrumentation, …)) — Grant relies on external Micrate and the Amber CLI for these operations; no Grant-level programmatic create/drop/purge/prepare API and no structure-dump load.
121. **Database tasks: create/drop database, purge, structure dump (structure.sql), setup/reset/prepare, truncate_all** (Migrations & schema) — No Grant API; Micrate/Amber CLI does create/drop only. No structure dump/load, purge, `db:prepare`, `db:reset`, or `truncate_all`.
122. **Schema format configuration (:ruby vs :sql) and db:schema:load for fresh environments** (Migrations & schema) — Depends on the schema dump row; nothing to select or load.
123. **Migration file generator naming conventions (AddXToY, CreateXs parse, timestamped versions)** (Migrations & schema) — Covered only inside the external Amber CLI row; no attribute parsing DSL in Grant.
124. **query_constraints composite model keys** (Infrastructure (locking, encryption, instrumentation, …)) — No API to scope find/update/destroy/reload by multiple columns while keeping a single-column primary key (for example a sharded or tenant-partitioned key).
125. **composite foreign keys on associations (query_constraints)** (Associations) — Association macros assume a single foreign key and primary key column; composite primary keys exist in src/grant/composite_primary_key.cr but associations do not use them.
126. **association option validation (unknown keys and dependent: values raise)** (Associations) — Macros take **options and ignore unknown keys; an invalid dependent: (e.g. :restrict_with_error, :delete on has_many) is silently accepted (probe P3). AR raises ArgumentError for both.
127. **nested has_many :through (through another through association)** (Associations) — AssociationCollection#through_associations does a single registry lookup; if the through association is itself a through, the join keys are wrong. No spec exists.
128. **singular association builders build_<assoc> / create_<assoc> / create_<assoc>!** (Associations) — Not generated (probe P6: responds_to?(:build_prb_detail) and :create_prb_detail are false).
129. **has_many :through source_type (polymorphic source)** (Associations) — No source_type option; a through whose source is a polymorphic belongs_to cannot be expressed.
130. **Adapter session variables (PostgreSQL statement_timeout/lock_timeout/search_path/application_name, MySQL variables/sql_mode)** (Adapters & connections) — There is no per-connection variables hook, so statement_timeout, lock_timeout, application_name, default search_path and MySQL sql_mode cannot be set declaratively; no per-query timeout. MySQL adapter only forces utf8mb4 encoding. Deferred: crystal-db has no on-connect hook, so this needs an upstream or wrapped-connection factory. A SET on every checkout would double round trips.
131. **Encryption: pluggable key_provider, encryptor, message_serializer, AES-GCM cipher** (Infrastructure (locking, encryption, instrumentation, …)) — KeyProvider is a concrete class with class-level state. Cipher is CBC+HMAC with a custom byte layout, so ciphertext is not interoperable with Rails data. No envelope-encryption provider (KMS) and no swappable encryptor. Deferred: Changing the cipher or payload layout breaks existing ciphertext. Needs a versioned payload design and a rotation plan first. Rails-compatible messages are a separate decision.
132. **Callback objects (before_save MyCallback.new / class with before_save(record))** (Validations & callbacks) — Callbacks accept a method Symbol or a block only; no object with a before_save(record) protocol for shared, testable callback classes. Deferred: Low value. A method Symbol or block already covers the use; the callback-object protocol adds compile-time surface for little benefit.
133. **Database-specific types: PostgreSQL hstore** (Infrastructure (locking, encryption, instrumentation, …)) — No Hash(String, String?) column type, no migration type or operators. Deferred: Low value, PG only, and JSONB covers the main use.
134. **Database-specific types: PostgreSQL ranges, network (inet/cidr/macaddr), interval, native enum, citext** (Infrastructure (locking, encryption, instrumentation, …)) — Only PG::Interval appears in the adapter's allowed type list and no spec covers it. No Range(T,T) column mapping, no Socket::IPAddress column, no PG CREATE TYPE enum mapping or citext. Deferred: Effort L, low value, and range bound normalization makes dirty tracking risky. Take individual types on demand.
135. **Generated (virtual/stored) columns** (Migrations & schema) — No DDL for generated columns; must use verbatim `column_type:`. Deferred: Low value and overlaps the Infrastructure virtual-column row. Verbatim column_type: works as a workaround. Do both together later.
136. **Lazy transactions (deferred BEGIN)** (Adapters & connections) — BEGIN is sent immediately on every transaction block, even ones that run no query or only reads that a cache satisfies; AR defers BEGIN until the first statement. Deferred: Low value, effort L, and lazy checkout mid-block risks starving the pool. Revisit after T01 lands and benchmarks show empty-transaction cost.
137. **Views (create_view/drop_view) and materialized views** (Migrations & schema) — No view DDL or view-backed model helpers; `view_exists?`/`views` introspection absent. Deferred: Low value, and needs PG-specific refresh semantics. Raw execute covers it until the DDL DSL (M02b) is stable.
138. **has_many :through disable_joins** (Associations) — No option; Grant's through query already uses an IN subquery rather than a JOIN, so cross-database through is not available. Deferred: Low value and effort M. Merge with Cross-database associations (has_many / has_one through with disable_joins: true), which is a duplicate. Revisit after A02.
139. **skip_callback / set_callback / define_callbacks / reset_callbacks (custom callback chains)** (Validations & callbacks) — No way to skip an inherited callback in a subclass or define new callback chains; runtime per-call skipping is impossible with compile-time chains. Callback chain is a compile-time constant, so run-time mutation is Ruby-metaprogramming-shaped. Deferred: Effort L, low value, and compile-time chains make Ruby-style runtime mutation a poor fit. Revisit after CB01.
